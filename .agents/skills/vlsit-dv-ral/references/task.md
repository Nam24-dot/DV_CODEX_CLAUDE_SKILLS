# Register review
An access policy string does not replace understanding of the field's hardware behavior. For side effects specify pre-read value, returned data and post-read/write state. Predict only observed completed successful accesses, with an explicit policy for error responses.

Validate endian conversion and byte lanes using asymmetric data patterns. Test partial writes and fields crossing bus words when supported. Do not assume every register supports backdoor access or that backdoor writes reproduce frontdoor side effects.

Skip generic bit-bash for volatile, destructive or unsupported fields using documented project mechanisms, then add behavior-specific checks. Verify HDL paths against elaborated hierarchy rather than guessing names from source.
